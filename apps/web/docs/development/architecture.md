## Layers

```text
src/app/              Routes, layouts, loading/error boundaries, metadata. Thin.
src/features/<x>/     UI + hooks for one module (today, inbox, calendar, habits, …)
src/components/ui/    Design-system components (no domain knowledge)
src/domain/           Pure TypeScript: types, rules, calculations. No React, no Next imports.
src/data/             Data access (server-only where it touches secrets or a database)
```

- `src/domain/` holds the logic shared in spirit with the mobile app:
  - timeline layout (`layoutDay`, `mapTimeToY`, gaps, slots), snapping and clamping, next free slot;
  - streaks, progress;
  - recurrence;
  - date and time formatting.
  Keep it framework-free and unit-tested. When the apps share code, this folder moves to `packages/domain` in the monorepo (W7).
- Feature folders compose components and hooks. Pages import features; features import `components/ui` and `domain`.

## Server and client components

- Default to **Server Components**. Add `"use client"` at the **leaf** that needs state, effects, event handlers, refs or browser APIs.
  - Client islands in the prototype: the timeline (drag, now line), week strip and date navigation, habit chips, the detail panel editor, the focus timer, toasts, the theme switch, capture fields.
  - The sidebar's static parts, headings, Upcoming and Goals lists can stay on the server.
- Pass serializable props from server to client. Do not pass functions except Server Actions.
- `server-only` code (database, secrets) lives in `src/data/` and imports `server-only`.
- With Cache Components on:
  - anything reading request data (`cookies()`, `headers()`, `searchParams`) or uncached fetches renders dynamically and needs a `<Suspense>` boundary close to it;
  - cacheable reads use `"use cache"` (plus `cacheLife` / `cacheTag`), and mutations revalidate by tag.
  Read `docs/01-app/01-getting-started/06-fetching-data.md` and the caching guides in the bundled docs before writing data code.
- `bun run build` is the check that catches prerender and caching mistakes. Run it after changing routes or data access.

## State

| State | Where |
|---|---|
| Selected date, selected activity, calendar view, project view | **URL** (`searchParams` / route params). Shareable, survives refresh, works with back/forward |
| Drafts, hover, open/closed, drag preview | Local `useState` / `useRef` in the client component that owns it |
| Theme | `<html>` class + persisted preference (W2) |
| Toast | One client provider in the root layout |
| Server data | Fetched in Server Components. Mutations through the W1 strategy; the UI updates optimistically (`useOptimistic`) for complete, move, resize and check-in, and rolls back with an error toast |

Do not add a global client store until a real cross-tree need appears.

## Dates and time

Activities use **floating local time**: `date: 'YYYY-MM-DD'` + `start` in minutes from midnight (see [product-overview](../product/product-overview.md#domain-model-from-the-prototype)).

- Never `new Date('YYYY-MM-DD')`: it parses as UTC. Construct local dates from parts.
- Weeks start on **Sunday**. Day range 05:00–24:00.
- **Server vs client time:** the server does not know the user's timezone or “now”. Anything that depends on now (today's date, the now line, active state, “left” labels) must be computed on the client, or from a timezone stored for the user. Render now-dependent UI in client components to avoid hydration mismatches. A `useNow()` hook ticks on minute boundaries and is injectable for tests.
- Formatting (`9:30–11:30 AM`, `1 hr 30 min`, `Thu, Nov 19`) lives in `src/domain/time.ts` so both apps produce the same strings. Use `Intl` with an explicit locale when localization arrives.

## Forms and validation

- Small forms (title, duration, color) are controlled client components in the detail panel. They save on change or blur, with optimistic UI.
- Create dialogs submit through the W1 mutation strategy (Server Actions with `useActionState` if W1 picks them).
- Validation functions live in `src/domain/` and return typed results. Run them on the client for instant feedback and again on the server.
- Error copy follows [interaction-patterns](../product/interaction-patterns.md#toast-copy).

## Errors

- `error.tsx` per route segment, `not-found.tsx` for unknown IDs, and inline errors with retry for failed mutations.
- Never render raw error messages. Log them on the server.

## Performance

- Server Components and partial prefetching handle most of it. Keep client bundles small by pushing `"use client"` down.
- Do not add `useMemo`/`useCallback`/`memo` by reflex (React Compiler).
- The timeline renders one day (tens of rows) with absolute positioning. No virtualization needed.
- Drag updates one preview state and recomputes the pure layout. Keep `layoutDay` cheap and allocation-light.
- Fonts via `next/font` only. Images via `next/image`.
